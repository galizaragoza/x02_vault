En primer lugar, averiguamos la IP de la máquina objetivo con `netdiscover` (previo `sudo su`)

```zsh
netdiscover

192.168.1.153   08:00:27:0f:a0:d0      1      60  PCS Systemtechnik GmbH
```

Una vez está clara la dirección del objetivo, se lanza un escaneo general para identificar servicios y versiones. En este caso, tenemos un servidor HTTP por el puerto 80 que muestra el mensaje por defecto de Apache, por otro lado hay otro servidor HTTP en el puerto 8080, cuyo `robots.txt` ya nos da un jugoso hilo del que tirar.

```zsh

|_http-title: Apache2 Debian Default Page: It works  
|_http-server-header: Apache/2.4.65 (Debian)  
8080/tcp open  http    Apache httpd 2.4.65 ((Debian))  
|_http-open-proxy: Proxy might be redirecting requests  
|_http-title: SULACO \xE2\x80\x94 Extraterrestrial Life Division  
| http-robots.txt: 1 disallowed entry    
|_/api/admin_flag.php  
|_http-server-header: Apache/2.4.65 (Debian)
```

En cualquier caso, lo lógico ahora es visitar la página. Dicha web es una especie de interfaz de monitorización de una expedición interestelar llamada *USS Sulaco* (una referencia a *Aliens*). Hay algunas stats estáticas. Sin embargo, hay un endpoint muy interesante, `/search.php`. El script que el endpoint utiliza para "buscar" está en el código fuente, y es vulnerable a XSS, sin embargo, no parece un vector de acceso a la máquina.

El XSS se puede demostrar con este payload

```js
<img src=x onerror=alert('XSS');>
```
