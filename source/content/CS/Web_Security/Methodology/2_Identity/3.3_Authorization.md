#reference #Web_Security

**Authorization (autorización)** = comprobar **qué puede hacer** un usuario ya autenticado. Los fallos de autorización (**Broken Access Control**, OWASP A01) son de los más críticos y comunes: acceder a recursos/acciones para los que no se tiene permiso.

> Autenticación = *quién eres*. Autorización = *qué puedes hacer*. El fallo típico: la app verifica lo primero pero no lo segundo en cada acción.

# Directory Traversal

Acceder a ficheros fuera del directorio previsto manipulando la ruta.

```
?file=../../../../etc/passwd
?file=..%2f..%2f..%2fetc%2fpasswd     # URL-encoded
....//....//etc/passwd                 # bypass de filtros simples
```

Mitigación: canonicalizar y validar rutas (allowlist), no construir rutas con input del usuario.

# Bypass de Autorización

| Técnica | Idea |
|---------|------|
| **Forced browsing** | Acceder directo a URLs/endpoints no enlazados (`/admin`). |
| **Parameter tampering** | Cambiar `role=user`→`admin`, `?userid=`. |
| **Method/verb tampering** | Usar `PUT`/`DELETE` donde solo se controla `GET`. |
| **Missing function-level AC** | Endpoint de API sin check de rol. |
| Manipular cookies/JWT | `isAdmin=true`, alterar claims. |

# Escalada de privilegios

| Tipo | Descripción |
|------|-------------|
| **Vertical** | Usuario normal → admin (más privilegios). |
| **Horizontal** | Acceder a datos de **otro usuario** del mismo nivel. |

# IDOR (Insecure Direct Object Reference)

Referencia directa a un objeto sin comprobar que el usuario tiene permiso sobre él.

```
GET /api/invoice/1001      ->  cambiar a /api/invoice/1002 (factura de otro)
GET /user/123/profile      ->  /user/124/profile
```

Mitigación: comprobar **ownership** en cada acceso (no confiar en IDs del cliente), usar referencias indirectas/UUID impredecibles, control de acceso server-side por objeto.

# Pruebas

Repetir cada acción con: otro rol, otro usuario, sin sesión. Comparar respuestas (Burp: *Autorize* / match-replace). Probar IDs incrementales.
