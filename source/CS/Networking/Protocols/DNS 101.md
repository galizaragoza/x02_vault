#reference #Networking

**DNS** (Domain Name System) = "agenda de Internet": traduce nombres de dominio (`ejemplo.com`) a direcciones IP. Sistema jerárquico y distribuido, cacheado a varios niveles.

> Teoría aquí. Para tipos de registro, comandos (`dig`/`nslookup`), AXFR y uso en recon → cheatsheet [[DNS_CS]].

# ¿Qué es un servidor DNS?

Servidor que responde consultas de resolución. Tipos por rol:

| Tipo | Función |
|------|---------|
| **Recursivo (resolver)** | Resuelve en nombre del cliente, consultando la jerarquía; cachea. Ej. `8.8.8.8`. |
| **Root** | Apuntan a los servidores TLD. |
| **TLD** | Autoritativos de `.com`, `.es`… |
| **Autoritativo** | Tiene la zona real del dominio (registros A, MX…). |

# Resolución

```
cliente -> resolver  (consulta recursiva)
resolver -> root -> TLD -> autoritativo  (consultas iterativas)
resolver -> cliente  (respuesta + cache)
```

### DNS forwarder

![[dns-forwarder.png|635x357]]

Además de reenviar las queries DNS a los servidores upstream, un **DNS forwarder** almacena en caché las respuestas, saltándose la consulta al servidor si ya la tiene cacheada → más rápido y menos tráfico externo.

# Caché y TTL

Cada registro tiene un **TTL** que indica cuánto puede cachearse. Caché a varios niveles: navegador, SO, resolver. Un TTL bajo permite cambios rápidos (y se abusa en [[Fast Flux]]).

# Seguridad

DNS sin cifrar es espiable y falsificable → [[!DNS Cache Poisoning]], [[DNS Tunneling]]. Mitigaciones: **DNSSEC** (firma respuestas), **DoT/DoH** (cifran el canal).
